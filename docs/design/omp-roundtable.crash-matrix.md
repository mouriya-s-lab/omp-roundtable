# omp-roundtable：崩溃矩阵

本文是 [omp-roundtable.md](omp-roundtable.md) §5 的附件。每一行列出一个崩溃窗口、重启或重试后看到的状态，以及恢复靠的是什么。所有恢复都通过下一轮推导读本地状态文件与 GitHub 源头来完成，没有单独的恢复流程。

| # | 崩溃窗口 | 重启 / 重试后的状态 | 恢复依据 |
|---|---|---|---|
| 1 | 回复已通过核验，状态文件写入成功，但响应丢失 | 重发同一回复；状态里已是新值 | `step` 第 1 步：状态里已是这条回复，返回 `Same`，回答「已生效」，不写 |
| 2 | 回复已通过核验，状态文件写入失败 | 席位收到错误，状态仍是旧值，票据仍未完结 | 席位重发；`yield` 拦截会保证它不会就此结束 |
| 3 | 写状态时版本比较交换失败（本进程另一轮先写了） | 状态文件是另一轮写入的新版本 | 重读后重算一次：票据已不存在就拒绝；仍然需要就按新版本写入 |
| 4 | 依据 `submit` 创建或更新 PR 已执行，结果没写回 | 状态里 `applied` 仍为假 | store 执行前按 head 分支查找 open PR，它的 head、标题与正文哈希已等于目标时不再写，只把结果写回 |
| 5 | `merge` 已执行，响应丢失 | 下一轮读到 PR 已合并 | `merge` 的前提（PR 为 open）不再成立 |
| 6 | 依据草稿创建 issue 后崩溃，结果没写回 | 状态里草稿还没登记 issue | store 执行前在目标 repo 里查找草稿提出之后创建、标题相同的 issue（GraphQL 连接，写后即读一致），找到就登记，不再创建 |
| 7 | 替换 issue 正文后崩溃，结果没写回 | 状态里替换仍未应用；当前正文哈希等于目标哈希 | 效应仍被推导；store 执行前核对到正文已等于目标，不写 GitHub，只写回结果。写回之后有人再改正文，替换也不会重新生效 |
| 8 | 关闭或重开 issue、parent 后崩溃 | 事件已在 GitHub 上 | 完成判定直接读 GitHub 事实，不需要写回 |
| 9 | 重跑 checks 后崩溃，结果没写回 | 状态里裁定仍是未执行 | 下一轮再重跑一次，然后写回。多出的一次 CI 运行不改变任何事实，所以不另设源头核对 |
| 10 | omp 进程在交付中途退出 | 进程内一切丢失，registry 为空；状态文件完好 | 操作员确认原会话已结束后，主会话恢复议程；状态里的持有者不在 registry 中，席位为 `absent`，core 给主会话派出票据；owner 按同一个请求名派出，回到同一个工作目录继续 |
| 11 | 席位会话 aborted | registry 状态为 aborted，席位算作 `absent` | 按同一个请求名派出续作席位，registry 追加 `-2` 后缀，去掉后缀后仍能匹配；gate 席位的请求名包含 pin 与尝试序号，所以只在输入没变时才续作同一次 gate |
| 12 | 写状态文件时中途崩溃 | 可能留下半截临时文件 | 先写临时文件再原子改名，读到的只会是完整的旧版本或新版本 |
| 13 | 状态文件丢失，或换了机器 | 议程不存在 | 议程不能恢复，这是操作员接受的代价（R11）。adapter 报告议程不存在，不从 GitHub 重建；重新召集时，已有的 PR 通过召集载荷指定接管 |
| 14 | 推导读取 GitHub 中途失败 | 没有完整的事实读数 | 本轮作废，不产生任何义务；adapter 把读取失败告诉主会话，下一次触发时重读 |
