# omp-roundtable：崩溃矩阵

本文是 [omp-roundtable.md](omp-roundtable.md) §5 的附件。每一行列出一个崩溃窗口、重启或重试后看到的状态，以及恢复靠的是什么。所有恢复都通过下一轮推导读到源头来完成，没有单独的恢复流程。

| # | 崩溃窗口 | 重启 / 重试后的状态 | 恢复依据 |
|---|---|---|---|
| 1 | 回复已准入，评论写成功，但响应丢失 | 席位重发同一回复；票据已完结，不再被推导 | `admit` 先按幂等键查找已有记录：载荷相同，返回 `Replayed`（已写入）；载荷不同，拒绝为「已完结」 |
| 2 | 回复已准入，评论写失败 | 席位收到错误，票据仍未完结 | 席位重发；`yield` 拦截会保证它不会就此结束 |
| 3 | 依据 `PrSubmit` 创建 PR 的效应已执行，响应丢失 | 下一轮读到带该 `PrSubmit` 标记的 PR | 效应条件不再成立，所以不重复创建 |
| 4 | `merge` 已执行，响应丢失 | 下一轮读到 PR 已合并 | `merge` 的前提（PR 为 open）不再成立 |
| 5 | 依据草稿创建 issue 后崩溃 | 带草稿 id 标记的 issue 已存在 | 议程由草稿记录加上已创建的 issue 计算得出，不需要写议程 |
| 6 | 替换 issue 正文后崩溃 | 正文里带着已应用的裁定 id 标记 | 效应条件不再成立；如果之后有人改了正文，基准哈希不符，不再覆盖 |
| 7 | 议程 issue 已创建，但关闭或挂到 parent 下失败 | 议程 issue 仍 open，或还没挂上 | 「议程 issue 必须已关闭并已挂好」是效应条件，下一轮补做 |
| 8 | omp 进程在交付中途退出 | 进程内一切丢失，registry 为空 | 操作员确认原会话已结束后，主会话恢复议程；registry 读数中席位为 `absent`，core 给主会话派出票据；owner 按同一个请求名派出，回到同一个工作目录继续 |
| 9 | 席位会话 aborted | registry 状态为 aborted，读数中算作 `absent` | 按同一个请求名派出续作席位，registry 追加 `-2` 后缀，去掉后缀后仍能匹配；gate 席位的请求名包含 pin 与尝试序号，所以只在输入没变时才续作同一次 gate |
| 10 | HMAC 密钥丢失或换了机器 | 议程上已有的记录全部验签失败 | adapter 检测到议程 issue 上有验签失败的系统记录时，停止推导，并作为阻塞报告主会话。不能当作「什么都没发生」重新开始，否则会重复写入。密钥迁移归 omp-config 的密钥迁移命令 |
| 11 | 本地后端写状态表时中途崩溃 | 状态表可能写了一半 | 本地后端写临时文件再原子改名，读到的只会是完整的旧版本或新版本 |
| 12 | 推导读取 GitHub 中途失败 | 没有 Snapshot | 本轮作废，不产生任何义务；adapter 把读取失败告诉主会话，下一次触发时重读 |
